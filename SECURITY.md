# Security Policy

## Supported Versions

| Version | Supported |
|---------|-----------|
| latest  | ✅ |
| older   | ❌ |

## Reporting a Vulnerability

OBSIDIOS is a defensive security tool, but vulnerabilities in the tool itself should be handled responsibly.

To report a security issue:

1. **Do not** open a public GitHub issue
2. Email the maintainers or open a draft [GitHub Security Advisory](https://github.com/idkgarvit/OBSIDIOS/security/advisories)
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact

You should receive a response within 48 hours. Once the issue is confirmed, a fix will be developed and released as quickly as possible.

## Scope

This policy covers:

- The OBSIDIOS codebase itself
- Docker configurations
- Default credentials and configurations

It does **not** cover:

- Vulnerabilities in third-party dependencies (report them to the respective maintainers)
- Networks you run OBSIDIOS against (ensure you have proper authorization)

## Responsible Disclosure

We request a 90-day disclosure window from the time a fix is released before public disclosure.
